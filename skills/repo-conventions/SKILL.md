# 目录、脚本与路径规约

## 目录结构与归档

| 目录 | 用途 |
| --- | --- |
| `scripts/<主题>/` | 分析与业务脚本，目录下通过 `SCRIPTS.md` 索引 |
| `data/<主题>/` | 清洗后的结构化中间数据 |
| `archive/<主题>/` | 原始采集数据与归档材料 |
| `output/<主题>/{report,img}/` | 最终交付的研究报告与图表文件 |
| `memory/<项目>/` | 知识沉淀文档与工作日志视图 |
| `tools/<工具>/` | 第三方依赖工具源码与预编译二进制，构建产物留在内部 |
| `repos/<名字>/` | 外部依赖或参考代码仓库，默认不纳入版本控制 |

- 主题归档：同一主题下的脚本、产出图片、数据集与文档统一收拢至该主题目录，不散落于仓库根目录或跨主题混放。
- 命名风格：主题名称推荐使用全小写蛇形（如 `etf_premium`）或精炼标识符，全库保持风格一致。

## 外部代码仓库管理（repos/）

当工作涉及分析或依赖外部开源项目时，外部代码统一存放于 `repos/`，避免与自研源码混合：

| 场景 | 推荐存放位置 | 组织方式 |
| --- | --- | --- |
| 参考、逆向或静态分析代码 | `repos/<名字>/` | clone 或 symlink |
| 需要编译、打补丁运行的第三方工具 | `tools/<名字>/` | 源码与构建产物保存在工具目录内 |
| 大型独立项目或完整框架 | `src/<主题>/<项目>/` | 独立子目录管理完整工程 |
| 小型自研复用模块 | `src/` | 供跨模块 import 的基础代码 |

- 外部仓库引入形式：
  - 远程克隆：`git clone <url> repos/<名字>`（推荐，自包含且版本受控）。
  - 本地软链：`ln -s <本地路径> repos/<名字>`（复用本机既有克隆），真实路径记入根目录 `.env`。
- 版本跟踪补偿：外部仓库默认配置于 `.gitignore`，须在 `memory/<项目>/` 中记录对应 URL、commit hash 或 tag，以及 patch 清单，确保环境可复现。
- 改动留痕：对外部代码的必要调整推荐生成补丁文件归档至 `patches/`，便于上游版本升级时重放。

## 脚本索引维护（SCRIPTS.md）

- 并行协作路径：多个 Agent 共同参与某一主题开发时，脚本存放于 `scripts/<主题>/<agent>/`；单 Agent 小型主题可直接存放在 `scripts/<主题>/`。
- 索引同步：每个 `scripts/<项目>/` 目录下维护 `SCRIPTS.md`，记录脚本职责、调用方式与参数说明；按 Agent 分目录时由根级 `SCRIPTS.md` 统一索引。
- 脚本资产保留：有明确功能价值的脚本即便后续废弃，优先移动至 `archive/` 留存历史过程，避免直接物理删除。

## 脚本编写规范（模块化与行数控制）

控制单文件规模有助于降低上下文消耗并提升可维护性：

- 入口精简：主入口文件（`main.py`、`run_*.py`）不超过 200 行，仅负责参数解析、模块调度与主流程串联，不堆砌业务计算细节。
- 模块单一职责：单模块源码不超过 300 行；按功能划分为数据采集（`fetch.py`）、数据清洗（`clean.py`）、指标计算（`indicators.py`）、绘图输出（`plot.py`）及配置参数（`config.py`）。
- 避免内联长数据：硬编码列表、大尺寸字典与复杂 SQL 提取至 `config.py` 或独立数据文件（CSV/JSON），不直接内嵌在主流程逻辑中。
- 小步修改原则：修改既有功能时优先定位关键代码段做局部更新，避免对整个文件执行无差别全量重写。
- 豁免范围：`multiagents/agentctl.py` 作为框架统一维护的基础控制工具，免除上述行数限制。

## 文本输出与多语言配置

面向用户的交互输出统一采用 `i18n.t("中文原文", **占位)`：
- 资源键名以中文原文为准，翻译文件维护于 `multiagents/locales/<lang>.json`；未命中翻译时回落为中文原文。
- 代码注释与技术文档保持中文书写。
- 语言加载优先级：CLI 运行参数 `--lang` 优先于环境变量 `AGENTCTL_LANG`，再次为配置文件 `multiagents/state/settings.json`。

## 通用文件修改互斥机制

代码库共享文件（如通用脚本、配置文件、技能事实源与规则说明）的修改应防范并发覆盖：
- 修改项目通用文件时，调用 `python3 multiagents/agentctl.py file edit|write|append <路径>`。该接口在写入时基于跨进程文件锁进行原子替换，并在 `multiagents/state/locks/edits.jsonl` 中留存审计记录。
- Agent 独占产物（如个人主题分析报告、私有测试数据）可直接编辑。
- 锁超时默认 30 秒，排队等待可附加 `--wait` 参数；文件锁随进程退出自动释放。

## 路径安全与隐私保护

- 消除绝对路径依赖：代码、配置及脚本中禁止出现含本机用户名的绝对路径（如 `/home/<user>/...`），确保仓库在不同机器之间可直接迁移。
- 本地路径外部化：机器特定的外部数据路径统一配置于项目根目录 `.env`，命名规范推荐采用 `<主题>_<用途>` 大写形式（如 `<主题>_DATA_ROOT`）；`.env.example` 提供公开参考模板。
- 路径缺省容错：路径解析逻辑在检测到 `.env` 变量缺失时，推荐回落至以当前脚本位置相对推导仓库根目录，保证基础分析代码能正常执行。

## 图片读取预处理

- 大图尺寸控制：在将分析产出的高分辨率图表载入上下文前，建议先等比缩放至最长边 618px 以内并压缩，避免占用过多上下文窗口。低分辨率图表或切片直接读取即可。
