# 量化分析防错规约

以下规则属通用陷阱，任何主题做量化分析都适用。**每条的实例就是判据**，写结论前逐条对照。

- **先确认变量的机制含义，再写结论**。写「买入/申购」「成交/换手」「流入/流出」这类词前，先问：**它在机制上影响哪个量？** 实例：场内「买入」是二级撮合、**不改变基金份额**；「申购」才增加份额。用"份额变化"解释"买入意愿"在机制上不成立（无因果通道），术语用错会让整节结论读反。
- **分组指标先查三件事**：① 拟解释的变量在机制上**能否被该分组影响**；② 两个变量是否**"定义上就绑定"**（实例：份额稳定 ↔ 暂停申购，暂停时份额必然不动，属同义反复，不能当因果证据）；③ **定序要看 T→T+1 事件次序**，只看同期分组几乎必然掺入机械关系。
- **字段的样本间可得性要先验证**：按某字段分组前，确认它在各子样本中**是否同等可得**，否则会把"数据缺失"误读为"机制差异"。实例：申赎状态字段对 LOF 完整、对 ETF 绝大多数记为"场内买入"，导致"通道关闭占比"在两类间不可比（7.1% vs 63.5%）。**该比例只在同类内部比较**。
- **反解/派生指标必须做「恒量时段」检验**：用 `A/B` 反解出的量（如用 `成交量 ÷ 换手率` 反解份额），必须先确认**分母的口径**——字段说明表没有公式就是**推断**。检验办法：**找一段"该量在机制上必须恒定"的时段**检查它。实例：暂停申购期份额只可能因赎回减少，但反解量段内波动 p90 达 216.7% → 该量含显著噪声，只能当**方向性代理**，不能当精确值。同时给出**噪声过滤后的稳健性表**（逐级收紧阈值看系数是否变号）。
- **多个独立数据源互相印证**：关键量尽量用**两个来源**交叉验证，二者同步才能排除单一来源的口径偏差。实例：两市成交额与两融余额（相关系数 0.878、融资买入额 0.962）。
- **报告的"勘误"本身也要复核**：核对口径时先确认聚合的**单位是什么**（交易日 / 基金日 / 品种），再判断谁的数对。"表面不一致"未必是报告错，也可能是核验脚本的聚合层级错。实例：曾把正确的逐日均值（17,028 亿）误改为按品种等权的错误口径（17,132 亿）。
- **委派出的数字必须复算**：subagent 会生成看似合理但**无法复现**的数字。素材/产出表里给它的数字可核对，**它自己"现算"的数字必须由主会话复算**，无法复现的一律替换为可复现口径。实例：凭空写出"54.8%"，实测 28.7%。
- **用户的事实性错误要搜索检验后纠正，不要顺着写**：用户口述的定义（换手率、Sharpe、折溢价口径等）若与原文/权威定义不符，流程是：① 先查原文/一手定义核实；② 用可复算方式演示差异（分位数互倒检验、量纲检查）；③ 明确指出错在哪、正确定义是什么、用户说法里哪部分仍成立。实例：用户称"换手率 = dollar 成交量/净资产"，原文实为 τ = 成交额(买+卖双边计)/多空名义本金之和；用户称"Sharpe = 单位风险/波动"，实为年化收益/年化波动 = √252·PnL/σ。顺从错误定义写进报告会让错误看起来像经双方确认。
- **自建的检查器/脚本本身也要验证覆盖范围**：写了 `style_lint.py` 这类校验工具后，必须用**已知的正例**去试它是否报得出来，否则会误以为"0 命中＝没问题"。实例：该脚本曾 `continue` 跳过所有标题行，导致标题里的违规从不被检查；修正后同一份报告由 0 命中变 2 命中。**检查器的漏检比被检查对象的错误更危险**，因为它给出虚假的通过信号。

## 收尾

- [ ] 关键派生量已确认口径来源（有公式才算实测，无公式按推断处理），必要时做过「恒量时段」检验
- [ ] 委派/现算的数字已复算；同一指标多口径时已指定唯一口径并写清定义
