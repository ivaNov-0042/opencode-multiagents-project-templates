# multi_agents_templates (Multi-Agent Research Workspace Template)

> [简体中文](README.md) · English · [日本語](README.ja.md)

This repository provides a foundational skeleton for coordinating multiple AI Agent sessions working in parallel within a shared workspace: covering session identity claiming, a team task board, shared memory decoupled into JSON Single Source of Truth (SSOT) and Markdown views, a CLI-neutral skill distribution mechanism, and cross-process lock-protected file editing interfaces.

## Quick Start

### For Humans:
1. Clone and enter directory: `git clone <repo-url> <workspace_name> && cd <workspace_name>`.
2. Launch your terminal environment and enter `/boot` (or any initial command to trigger onboarding).
3. The onboarder `00_yuki` will guide you step-by-step: confirming your interaction language, planning research topics, configuring environment variables, and claiming agent identities.

### For AI Agents:
1. First step of every session: run `python3 multiagents/agentctl.py me` to confirm the agent identity bound to the current session.
2. Upon identification, load the corresponding skills (`skills[]`) prompted by your identity card; if unmatched, present the roster for user selection—never assume an identity.
3. Edit workspace-common files via the lock interface (`python3 multiagents/agentctl.py file`), maintain task lifecycle via `agentctl.py todo`, and persist analysis findings to shared memory (`agentctl.py memory`).

## Architecture Background

In modern AI-assisted engineering workflows, developers frequently parallelize complex tasks across multiple sessions, multiple windows, or different client environments (such as Antigravity, OpenCode, Claude Code, and Codex). Without coordination protocols, several frictions arise: parallel sessions compete for the same role, concurrent file writes silently overwrite each other, context loss leads to redundant troubleshooting, and prompt rules drift across client directories.

This project abstracts the minimal essential mechanisms needed for multi-agent collaboration:
- **Unified Control Layer**: Pure Python standard library script `agentctl.py` provides centralized management for identity allocation, task boards, shared memory, and locked file editing.
- **Single Source of Truth (SSOT)**: Task boards and memory records use JSON as the SSOT, while human-readable Markdown views are automatically generated by scripts to prevent parsing drifts.
- **CLI-Neutral Skills**: Skills are authored once in `skills/` as SSOT and automatically mirrored to each client's configuration directory.

## Compatible Agents & Client Environments

The framework automatically recognizes sessions via environment identifiers, providing seamless support for mainstream Agent CLIs and IDEs:
- **Antigravity**: Automatically detects `ANTIGRAVITY_AGENT` and `ANTIGRAVITY_CONVERSATION_ID` session variables, with skills mirrored to `.agents/skills/`.
- **OpenCode**: Supports multi-window TUI session probing, includes built-in `/boot` shortcut plugin (in `.opencode/plugins/multiagents/`), with skills mirrored to `.opencode/skills/`.
- **Claude Code**: Supports standalone terminal session detection, with skills mirrored to `.claude/skills/`.
- **Codex / CodeBuddy and others**: Supports environment indicator probing and the `.agents/` open skill directory specification.

## Core Mechanisms Comparison

| Problem Scenario | Framework Solution |
| --- | --- |
| Multi-session identity collisions | Session startup runs `agentctl.py me` to auto-match profiles by session ID; unmatched sessions prompt user selection |
| Disconnected task division & progress | Team task board `todo` (JSON SSOT, `TODO.md` view) tracks claims, handoffs, and completion; private tasks tracked via `task` |
| Overwriting and losing shared knowledge | Memory SSOT is organized by section with locked writes; multiple agents append to dedicated independent sections |
| Skill rules drifting across clients | Centrally maintained in `skills/<id>/SKILL.md` and mirrored to each CLI directory via `sync_skills.py` |
| Concurrent file edit overwrites | Common files are edited via `agentctl.py file` with flock mutex + atomic replacement + full audit logging |

## Directory Structure

| Directory / File | Description |
| --- | --- |
| `AGENTS.md` | Core rules, constraints, and index pointers for AI Agents |
| `multiagents/` | Framework CLI tools, roster profiles, SSOT data (`state/`), and protocol specifications |
| `skills/` | Skill Single Source of Truth (CLI-neutral), one directory per skill |
| `memory/` | Shared knowledge and research diary views (`.md` is read-only export; SSOT in `multiagents/state/memory/`) |
| `scripts/` | Topic-organized analysis scripts, indexed internally by `SCRIPTS.md` |
| `repos/` | External dependencies or reference repositories, excluded from git tracking by default |
| `data/` | Cleaned structured intermediate datasets |
| `output/` | Final deliverables (analysis reports and charts) in `output/<topic>/{report,img}/` |
| `TODO.md` | Exported view of team task board (SSOT is `multiagents/state/todo.json`) |
| `tools/` | Third-party dependency tools and build directories |

## Why `xxxx/<topic>/xxx` Directory Design Empowers Vibe Coding

When engaging in high-velocity, intuition-driven AI programming (**Vibe Coding**), developers and AI agents frequently hit major engineering bottlenecks: context windows clogged by unrelated files, root directories littered with throwaway test scripts, unrepeatable one-off experimental results, and parallel sessions clobbering each other's work.

This framework enforces **`xxxx/<topic>/xxx` (Topic-Based Isolation)** and **`scripts/<topic>/<agent>/` (Dedicated Agent Playgrounds)** specifically to turn Vibe Coding from an ephemeral, messy hackathon into a sustainable, high-velocity engineering workflow:

1. **Strict Context Boundaries (Zero Token Pollution)**: When an agent vibes on a specific domain (e.g. `ai_tts`), it only scans `scripts/ai_tts/`, `data/ai_tts/`, and `memory/ai_tts/`. Unrelated code (e.g. low-level emulator disassembly) never enters the prompt context. This maximizes signal-to-noise ratio, conserves token budgets, and prevents LLM attention degradation and hallucinations.
2. **Ultra-Low Blast Radius (Safe Playgrounds)**: Vibe coding thrives on bold experiments and throwaway prototypes. In `scripts/<topic>/<agent>/`, each agent has an isolated sandbox to churn out quick probes and test scripts without fearing breaking mainline code or disturbing peers. Validated scripts graduate to `SCRIPTS.md`, while discarded experiments move cleanly to `archive/<topic>/`.
3. **Reproducible Pipeline Closed Loop**: From `archive/<topic>/` (raw inputs) ➔ `data/<topic>/` (structured datasets) ➔ `scripts/<topic>/` (execution logic) ➔ `output/<topic>/` (reports and visualization plots) ➔ `memory/<topic>/` (distilled insights and diaries), every deliverable maintains a rigorous audit trail. No more "it worked at 2 AM on my machine, but nobody knows which script generated it."
4. **Multi-Session Parallelism Without Race Conditions**: Developers can run multiple parallel sessions (e.g. Antigravity, OpenCode, Claude Code) working on different topics simultaneously. Isolated directories combined with cross-process file locks ensure uninterrupted parallel vibes with zero collision.
5. **Human Shifts from "Coder" to "Director"**: Deliverables strictly land in `output/<topic>/{report,img}/`. The human developer is freed from tedious line-by-line code review, instead assessing visual plots and concise markdown digests to provide instant directional steering for the next vibe iteration.

## Custom Project Adaptation

This template contains no proprietary domain logic. The typical workflow to adapt it to a new project:
1. **Add research topics**: Run `python3 multiagents/agentctl.py todo topic add "topic_name"`.
2. **Establish directory skeleton**: Create `scripts/<topic>/`, `data/<topic>/`, and `output/<topic>/{report,img}/`.
3. **Extend domain skills**: Author specialized operational guides in `skills/<id>/SKILL.md` and register them in the `AGENTS.md` skill map.
4. **Configure local paths**: Copy `.env.example` to `.env` and fill in machine-specific paths (`.env` is ignored by git).

## Multilingual Support

CLI output is driven by localized resource catalogs. The codebase calls strings via `i18n.t("原文", **kwargs)`, where the original Chinese string serves as the dictionary key, and translations reside in `multiagents/locales/<lang>.json`.
- View or switch language: `python3 multiagents/agentctl.py lang [code]`
- Extract and validate translations: `python3 multiagents/i18n_extract.py --check`
