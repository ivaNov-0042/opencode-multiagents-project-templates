Architecture Background

Modern AI-assisted development widely supports multi-window and multi-session concurrency. Developers can work on complex tasks across parallel sessions (Antigravity, OpenCode, Claude Code, Codex) within the same project, but each session operates in isolation, unaware of the others.

Without coordination protocols, multiple friction points arise: concurrent sessions compete for the same role, simultaneous file edits silently overwrite each other, fragmented session notes overwrite one another, task ownership remains opaque, and skill configurations drift across different client directories. The absence of collaboration mechanisms directly limits multi-agent parallel efficiency.

This project provides a lightweight multi-agent collaboration skeleton: A single Python stdlib CLI (agentctl.py) manages identity allocation, team task boards, shared memory, and locked file editing; Sessions bind identities at startup, shared files are guarded by cross-process file locks, memory documents are appended in dedicated sections, and skills are maintained in a single source of truth automatically mirrored to all client directories.

Core Problems Solved

Automatic Identity Binding

Session startup runs me to match agent profiles by client environment and session ID; falls back to interactive roster selection rather than guessing (exit code 3).

Transparent Task Flow

Team board todo supports claiming, handoff notes, and completion states; agents also maintain private task checklists for step breakdown.

Non-Overwriting Memory

Memory content uses JSON as single source of truth with auto-exported Markdown views; agents append dedicated sections without collisions.

Consistent Skill Sync

Single source of truth in skills/, mirrored via sync_skills.py to Antigravity (.agents), OpenCode, and Claude Code; --check verifies parity.

Lock-Protected Edits

Shared project files are edited via agentctl.py file: cross-process flock + atomic replace via temp files + audit log in edits.jsonl.

Closed-Loop Self-Check

init verifies field reference integrity; read-only .tests regression suite covers core invariants.

Quick start

User Workflow

Clone the workspace and launch your agent environment:

# 1. Clone the template
git clone <repo-url> <workspace_name>
# 2. Enter workspace
cd <workspace_name>
# 3. Launch your agent environment (Antigravity, OpenCode, Claude Code, etc.)
# In OpenCode type /boot; Antigravity sessions load project rules on startup

Guide 00_yuki assists with initialization: interaction language, research topics, environment variables, and role claiming.

AI Agent Workflow

Standard agent session workflow:

# 1. Clone and enter directory (AGENTS.md, skills, and configuration take effect immediately)
git clone <repo-url> <workspace_name>
cd <workspace_name>

# 2. First step of every session: verify identity
python3 multiagents/agentctl.py me
#    Auto-detects Antigravity, OpenCode, Claude Code session identity; prompts user with roster if unmatched.

# 3. Load skills listed in profile (skills[]) using the skill tool

# 4. If onboarding is incomplete, follow skill first-run steps 1–8

# 5. Execute tasks: edit shared files through locks (file / todo / memory); verify with init / verify / .tests

Detailed protocols live in skills multiagent-workflow and first-run; AGENTS.md defines core workspace constraints and index pointers.

agentctl Design Highlights

Unified CLI architecture, file locking, and data storage design overview. Full specification in multiagents/DESIGN.md:

Unified CLI Entry

Roster, task boards, memory, profiles, and locked edits are consolidated into agentctl.py for deterministic invocation.

File Locks & Atomic Replace

Shared writes use cross-process flock and atomic temp-file replace, logged in edits.jsonl for auditability.

Single Source of Truth & Views

Coordination state (profiles / todo / memory) uses JSON as single source of truth; Markdown serves as read-only export view.

Automatic Identity Protocol

Session startup runs me to bind client and session ID; unrecognised sessions exit with code 3 and show roster.

Computed Over Declared

Drift, dependencies, and onboarding progress are computed directly from the filesystem rather than trusting static claims.

Read-Only Regression Suite

Read-only regression suite .tests verifies invariants, read-only surface, field integrity, and mirror sync.

rigorous-writingRigorous style gate: style_lint.py automated check for AI clichés (bold density, dashes, false contrasts), 11-point self-test

All skills are maintained as a single source of truth in skills/<id>/SKILL.md and mirrored by sync_skills.py into .agents (Antigravity), .opencode, and .claude. Use --check to detect drift. Add project-specific skills using the same pattern.
