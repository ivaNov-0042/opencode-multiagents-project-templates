面向 Antigravity、OpenCode、Claude Code 等主流 Agent 环境的多会话协同骨架：涵盖会话身份自动绑定、团队任务板、JSON 单一事实源记忆、CLI 中立技能分发与跨进程加锁编辑。纯 Python 标准库，克隆即用。

快速开始 GitHub 仓库

架构背景

现代 AI 辅助研发广泛支持多窗口与多会话并行。 开发者可以在同一项目中通过多个会话（Antigravity、OpenCode、Claude Code、Codex）并行处理复杂任务，但各会话独立运行、互不知情。

在缺乏协同协议时，容易产生多重冲突：不同会话争抢同一身份、并发编辑相同文件导致改动覆盖、各会话记录的笔记零散互覆、无法确知他人认领状态、以及不同客户端之间的技能配置发生漂移。协作机制的缺失直接限制了多 Agent 并行效能。

本项目提供轻量级多 Agent 协同骨架： 基于纯标准库的 agentctl.py 统一管理身份分配、团队任务板、共享记忆与加锁编辑； 会话启动首先完成身份匹配，通用文件写入由跨进程文件锁保护，记忆按小节独立追加，技能定义以单一事实源自动镜像同步至各客户端目录。

核心解决问题

身份自动绑定

会话启动第一步运行 me，自动按客户端环境与会话 ID 检索匹配档案；未匹配时列出名册供使用者选定。

任务透明流转

团队任务板 todo 支持认领、备注与完成标记；各 Agent 另有专属私有清单 task 拆解步骤。

记忆不互覆

记忆正文以 JSON 为单一事实源，Markdown 自动导出视图；各 Agent 在独立小节追加，互不干扰。

技能一致同步

技能单一事实源位于 skills/，通过 sync_skills.py 自动镜像至 Antigravity（.agents）、OpenCode 与 Claude Code，--check 验证一致性。

并发加锁编辑

项目通用文件通过 agentctl.py file 加锁修改：跨进程 flock 互斥 + 临时文件原子替换 + 审计留痕。

自检完整闭环

init 核对字段引用完整性，只读回归测试套件 .tests 覆盖核心不变量。

AI Agent 操作

面向 Agent 的会话接入标准流：

# 1. 克隆并进入目录（AGENTS.md、技能单一事实源与配置克隆即生效）
git clone <repo-url> <workspace_name>
cd <workspace_name>

# 2. 会话启动第一步：确认身份
python3 multiagents/agentctl.py me
#    自动识别 Antigravity、OpenCode、Claude Code 会话标识；未匹配时列出名册供用户选择。

# 3. 按身份卡提示，使用 skill 工具加载对应技能集合（skills[]）

# 4. 未完成初始化时，遵循 skill first-run 推进 1–8 步引导

# 5. 执行任务：通用文件写入走锁（file / todo / memory），收尾运行 init / verify / .tests

详细规程见 skill multiagent-workflow（协同）与 first-run（初次安装）； AGENTS.md 包含工作区核心硬约束与索引指针。

目录分工

目录用途说明
multiagents/框架本体：agentctl.py（统一控制工具）、名册档案、单一事实源 state/、测试套件 .tests/
skills/技能单一事实源（CLI 中立），镜像分发至 .agents / .opencode / .claude
scripts/按主题组织的业务脚本，多 Agent 协作时置于 scripts/<主题>/<agent>/
repos/ tools/外部依赖代码仓库（clone 或 symlink） / 第三方工具构建目录
src/自研复用模块或独立项目工程（src/<主题>/<项目>/）
data/ archive/ output/清洗数据集 / 原始数据归档 / 交付报告与图表（output/<主题>/{report,img}）
memory/共享知识与日志视图（.md 为只读导出物，事实源在 multiagents/state/memory/）

agentctl 设计要点

单 CLI 架构、文件锁控制与数据存储设计速览，完整设计说明见 multiagents/DESIGN.md：

统一 CLI 入口

名册、任务板、共享记忆、档案属性与加锁编辑统一收敛至 agentctl.py，提供确定性调用入口。

文件锁与原子替换

通用写入操作由 flock 跨进程互斥保护，采用临时文件写入后原子替换，留痕于 edits.jsonl 可审计。

单一事实源与视图

协同状态（档案 / todo / 记忆）以 JSON 为单一事实源，Markdown 为只读导出视图；人读 md，机器读写 json，更新后自动重导。

自动身份协议

会话启动执行 me 自动基于客户端环境与会话 ID 检索档案；未匹配时列出名册供用户明确选定，不自行推定认领（退出码 3）。

环境现算优先

镜像漂移、依赖安装、就绪进度等状态直接基于文件系统现场判定，不依赖档案静态声称。

只读回归自检

只读测试套件 .tests 覆盖核心不变量、只读接口行为、字段引用完整性与技能镜像一致性。

技能体系（Skills）

模板预置 7 个 CLI 中立的技能单一事实源，认领身份后按需注入上下文，涵盖研发全流程工程规范：

技能 ID能力说明
first-run初次运行 8 步引导：确认输出语言、规划主题、配置 .env，协助新工作区环境就绪
multiagent-workflow多 Agent 协同规范：身份绑定、任务认领与流转、记忆小节追加、加锁编辑与收尾自检
repo-conventions工程规约：主题归档规则、scripts/<主题>/<agent>/ 结构、脚本资产留存、模块化与行数硬约束
report-writing交付报告架构：output/<主题>/report/ 目录规范、论据图表引用与数据结论核验
plotting-standards数据可视化标准：统一配色尺寸、图注格式与输出路径规范
quant-analysis-rules数据分析防错准则：数据核对、显著性说明、防过拟合操作规范
rigorous-writing严谨文风门禁：style_lint.py 自动化检查 AI 腔（加粗密度/破折号/假靶子句式），附 11 项规则自检

所有技能以单一事实源维护（skills/<id>/SKILL.md），通过 sync_skills.py 镜像至 .agents（Antigravity）、.opencode 与 .claude 目录， --check 检查漂移。新增业务技能遵循相同模式。
