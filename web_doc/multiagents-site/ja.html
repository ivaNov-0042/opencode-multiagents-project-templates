設計の背景

現代の AI 支援開発では、マルチウィンドウや複数セッションの並行動作が広く使われています。 開発者は同一プロジェクト内で複数のセッション（Antigravity、OpenCode、Claude Code、Codex）を立ち上げ、複雑なタスクを並列処理できますが、各セッションは互いに孤立し、存在を認識していません。

協調プロトコルがない場合、様々な問題が発生します：同一ロールの取り合い、同一ファイルへの同時編集による更新消失、セッションごとに作成されたメモの相互上書き、担当タスクの不透明さ、クライアントディレクトリ間でのスキル設定のズレなどです。協調メカニズムの欠如が、マルチ Agent の並行効率を直接制限しています。

本プロジェクトは、軽量なマルチ Agent 協調の骨格を提供します： 標準ライブラリのみで書かれた agentctl.py が、アイデンティティ割り当て、チームタスクボード、共有メモリ、ロック付きファイル編集を一元管理します。 セッション起動時にアイデンティティを自動紐付けし、共通ファイルへの書き込みはプロセス間ファイルロックで保護され、メモリは各セクションに追記され、スキルは単一事実源から各クライアントディレクトリへ自動ミラー同期されます。

解決する主な課題

アイデンティティ自動紐付け

セッション開始時に me を実行し、クライアント環境とセッション ID からプロファイルを照合。未一致時は名簿を提示してユーザーが選択（終了コード 3）。

タスクの透明な流通

チームタスクボード todo で担当割り当て、引き継ぎメモ、完了管理。Agent ごとのプライベートチェックリスト task も提供。

上書きされないメモリ

メモリは JSON を単一事実源とし、Markdown は自動エクスポートビュー。各 Agent が独立セクションに追記し衝突を防止。

ズレのないスキル同期

skills/ を単一事実源とし、sync_skills.py で Antigravity（.agents）、OpenCode、Claude Code へミラー。--check で整合性を検証。

ロック保護付き編集

共通ファイルは agentctl.py file 経由で編集：プロセス間 flock + 一時ファイルによるアトミック置換 + edits.jsonl への監査ログ。

自己完結の整合性検査

init でフィールド参照を検証。読み取り専用の .tests 回帰テストスイートで不変量をカバー。

クイックスタート

人間向けの手順

ワークスペースをクローンし、Agent 環境を起動します：

# 1. テンプレートをクローン
git clone <repo-url> <workspace_name>
# 2. ディレクトリに移動
cd <workspace_name>
# 3. Agent 環境を起動（Antigravity、OpenCode、Claude Code など）
# OpenCode では /boot を入力。Antigravity では起動時にプロジェクトルールが自動適用されます

案内役の 00_yuki が初期化をサポートします：対話言語の確認、研究テーマの計画、環境変数の設定、ロールの割り当て。

AI Agent 向けの手順

Agent 向けの標準セッションフロー：

# 1. クローンしてディレクトリに入る（AGENTS.md、スキル単一事実源、設定は即時有効）
git clone <repo-url> <workspace_name>
cd <workspace_name>

# 2. セッションの最初の一歩：アイデンティティ確認
python3 multiagents/agentctl.py me
#    Antigravity、OpenCode、Claude Code のセッション識別子を自動判定。未一致時は名簿を提示。

# 3. プロフィールの skills[] に記載されたスキルを skill ツールでロード

# 4. 初期化が未完了の場合は、skill first-run の 1–8 ステップに従って進行

# 5. タスク実行：共通ファイルの編集はロック経由（file / todo / memory）。完了時に init / verify / .tests で確認

詳細な規程は skill multiagent-workflow（協調）および first-run（初回セットアップ）を参照。 AGENTS.md にはワークスペースの主要な制約が記載されています。

ディレクトリ構成

ディレクトリ用途説明
multiagents/フレームワーク本体：agentctl.py（統一 CLI）、名簿プロファイル、state/ 単一事実源、.tests/
skills/スキル単一事実源（CLI 中立）、.agents / .opencode / .claude へミラー
scripts/テーマ別スクリプト。並行作業時は scripts/<テーマ>/<agent>/
repos/ tools/外部依存リポジトリ（clone または symlink） / サードパーティツールのビルド領域
src/再利用モジュールまたは独立プロジェクト（src/<テーマ>/<プロジェクト>/）
data/ archive/ output/整形データ / 原本アーカイブ / 成果物レポート・図（output/<テーマ>/{report,img}）
memory/共有ナレッジ・日誌ビュー（.md はエクスポートビュー。ソースは multiagents/state/memory/）

agentctl 設計の要点

統一 CLI 構成、ファイルロック、データ保管設計の概要。完全な設計書は multiagents/DESIGN.md：

統一 CLI エントリ

名簿、タスクボード、メモリ、プロファイル、ロック付き編集を agentctl.py に集約し、決定論的な操作を提供。

ファイルロックとアトミック置換

すべての共有書き込みでプロセス間 flock とアトミック置換を使用し、edits.jsonl に監査ログを残す。

単一事実源とビュー

協調状態（プロファイル / todo / メモリ）は JSON を単一事実源とし、Markdown は読み取り専用ビュー。

アイデンティティ自動プロトコル

セッション開始時に me でクライアント環境とセッション ID を照合。未一致時は終了コード 3 で名簿を提示。

実測優先の判定

ミラーのズレ、依存関係、オンボーディング進捗はファイルシステムから直接算出。

読み取り専用回帰テスト

読み取り専用テストスイート .tests が不変量、読み取り面、フィールド整合性、ミラー同期を検証。

スキル体系（Skills）

テンプレートには 7 つの CLI 中立なスキル単一事実源が同梱され、アイデンティティ紐付け後に必要に応じてコンテキストへ注入されます：

スキル ID機能概要
first-run初回起動 8 ステップ案内：対話言語確認、テーマ計画、.env 設定、環境準備
multiagent-workflowマルチ Agent 協調規程：アイデンティティ紐付け、タスク割り当て/引き継ぎ、セクション追記、ロック付き編集、完了時自己検査
repo-conventionsエンジニアリング規約：テーマ別アーカイブ規則、scripts/<テーマ>/<agent>/、スクリプト資産保全、モジュール化上限（≤200/≤300 行）
report-writing成果物レポート構成：output/<テーマ>/report/ 構成、根拠図表引用、検証可能な結論提示
plotting-standardsデータ可視化規格：統一配色・サイズ、キャプション書式、出力パス
quant-analysis-rules定量分析規準：データ照合、有意性表現、過学習防止の規律
rigorous-writing厳密な文体ゲート：style_lint.py による AI 構文の自動検査（太字密度、ダッシュ、対比構文）、11 項目のセルフチェック

すべてのスキルは skills/<id>/SKILL.md で単一事実源として管理され、sync_skills.py によって .agents（Antigravity）、.opencode、.claude にミラーされます。--check でズレを検出できます。プロジェクト固有スキルも同じ形式で追加します。
